# Прогноз оттока абонентов оператора связи

Проект по анализу оттока клиентов и построению модели, которая предсказывает, расторгнет ли абонент договор с оператором связи.

## Цель проекта

Оператор связи хочет заранее определять клиентов, которые собираются уйти, чтобы предложить им персональные условия и снизить отток.  
Нужно обучить модель, которая по данным о клиенте, договоре и подключённых услугах прогнозирует, будет ли договор активен или завершён (`is_active`).

## Данные

Используются табличные данные из четырёх файлов:

- информация о договоре (`contract_new`);
- персональные данные клиента (`personal_new`);
- информация об интернет-услугах (`internet_new`);
- информация об услугах телефонии (`phone_new`).

В ноутбуке реализована загрузка данных:
- либо из локальной папки `/datasets/…`,
- либо по прямым ссылкам с S3 Яндекс-практикума.

## Этапы работы

1. **Загрузка и первичный анализ данных**
   - проверка на пропуски и дубликаты;
   - проверка типов данных;
   - поиск «невидимых строк» в признаке `TotalCharges`.

2. **Предобработка**
   - приведение `TotalCharges` к типу `float`;
   - приведение `BeginDate` и `EndDate` к типу `datetime`;
   - выделение целевого признака `is_active` (1 — договор активен, 0 — завершён);
   - разработка логики заполнения пропусков в `EndDate` и признаках услуг;
   - объединение всех таблиц в один датафрейм.

3. **Исследовательский анализ данных (EDA)**
   - анализ распределений числовых и категориальных признаков;
   - изучение связи длительности договора, ежемесячных платежей и оттока;
   - кластеризация по `MonthlyCharges` с помощью `KMeans` и выделение типов тарифов;
   - построение корреляционной матрицы (phik) и визуализаций.

4. **Feature engineering**
   - создание признаков длительности и трендов платежей (`duration`, `avg_monthly`, `trend_ratio`, `trend_month`, `pred_total` и др.);
   - бинарные признаки наличия интернета/телефонии (`has_internet`, `has_phone`);
   - признаки типов услуг и тарифов.

5. **Подготовка данных к моделированию**
   - кодирование категориальных признаков с помощью `OneHotEncoder`;
   - масштабирование числовых признаков с помощью `StandardScaler`;
   - разбиение на обучающую и тестовую выборки.

6. **Моделирование**
   - baseline-модель (`DummyClassifier`);
   - модели:
     - `RandomForestClassifier`,
     - `CatBoostClassifier`;
   - поиск гиперпараметров для CatBoost через `RandomizedSearchCV` с кросс-валидацией (`cv=5`) и метрикой `accuracy`.

7. **Оценка качества**
   - метрики: `accuracy`, `roc_auc`, precision, recall, F1;
   - анализ матрицы ошибок;
   - сравнение с baseline.

8. **Интерпретация модели**
   - анализ важности признаков (`permutation_importance`);
   - интерпретация через `shap.TreeExplainer` (SHAP values);
   - выделение ключевых факторов риска оттока.

## Результаты

- Лучшая модель: **CatBoostClassifier**.
- Качество на тестовой выборке:
  - `accuracy` ≈ 0.93,
  - `roc_auc` ≈ 0.93.
- Модель значительно превосходит baseline (`DummyClassifier`) по ROC-AUC.

Модель позволяет заранее выделить группу риска среди абонентов, что даёт бизнесу возможность:
- точечно предлагать промокоды и специальные условия;
- снижать потери от оттока и оптимизировать работу с клиентской базой.
